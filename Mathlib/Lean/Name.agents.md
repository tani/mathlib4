### Technical Metadata Brief

#### 1. **Key Definitions & Theorems**
| Name | Type | Purpose |
|------|------|---------|
| `isBlackListed` | `Name → CoreM Bool` | Determines whether a declaration name should be excluded from analysis (e.g., internal, auxiliary, or Lean-internal names). |
| `allNames` | `(Name → Bool) → CoreM (Array Name)` | Collects all names in the environment satisfying a predicate, excluding blacklisted ones. |
| `allNamesByModule` | `(Name → Bool) → CoreM (Std.HashMap Name (Array Name))` | Groups names satisfying a predicate by their defining module, excluding blacklisted ones. |
| `Lean.Name.decapitalize` | `Name → Name` | Decapitalizes the last component (string segment) of a `Name`. |
| `Lean.Name.isAuxLemma` | `Name → Bool` | Checks if a name matches the pattern of auxiliary lemmas generated by `Lean.Meta.mkAuxLemma` (ends in `_auxLemma.nn`). |
| `Lean.Meta.unfoldAuxLemmas` | `Expr → MetaM Expr` | Expands all auxiliary lemmas (identified via `isAuxLemma`) in an expression using `deltaExpand`. |

#### 2. **Naming Conventions**
- **Predicates**: `is*` (e.g., `isBlackListed`, `isAuxLemma`) for boolean-valued functions.
- **Collection functions**: `all*` (e.g., `allNames`, `allNamesByModule`) for environment-wide queries.
- **Module grouping**: `allNamesByModule` uses `Std.HashMap Name (Array Name)` where the key is the module name (`Name`).
- **Auxiliary lemma pattern**: Ends in `_auxLemma.nn`, where `nn` is a numeric suffix (e.g., `_auxLemma.1`).
- **Decapitalization**: `decapitalize` suffix for string-case manipulation.

#### 3. **Tactic Stack**
- **Core monad operations**: `do`, `←`, `match`, `if ... then ... else`
- **Environment traversal**: `.constants.foldM` (used in `allNames` and `allNamesByModule`)
- **Pattern matching on `Name`**: `n matches .num (.str _ "_auxLemma") _`
- **Delta expansion**: `deltaExpand` (from `Lean.Meta.Tactic.Delta`)
- **No explicit tactic usage** — this is a *library file* (not a tactic file), so proofs are written in `do`-notation using Lean’s metaprogramming API.

#### 4. **Proof Logic / Implementation Pattern**
- **Stateful traversal**: Uses `foldM` over environment constants to accumulate results.
- **Filtering logic**: Combines user predicate `p` with negated `isBlackListed` check.
- **Module grouping**: Uses `findModuleOf?` to extract module name; falls back to `none` if module not found.
- **HashMap update idiom**: Manual `match` on `names[m]?` to insert/update arrays (noted as TODO for future `modify`/`alter`).
- **Pattern-based name recognition**: Relies on structural matching on `Name` (e.g., `n matches .num (.str _ "_auxLemma") _`).

#### Notes
- **No theorems** — this is a *utility module* for metaprogramming, not a logical development.
- **Blacklisting strategy** is conservative: excludes Lean internals, internal details, auxiliary recursors, no-confusion lemmas, and general recursors/matchers.
- **Module extraction** depends on `findModuleOf?`, which may return `none` for names not tied to a module (e.g., anonymous or synthetic names).
