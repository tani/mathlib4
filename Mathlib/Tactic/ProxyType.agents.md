### **Technical Brief: Proxy Type Generation in `Mathlib.ProxyType`**

#### **1. Key Definitions & Theorems**

| Name | Type / Purpose |
|------|----------------|
| `ProxyEquivConfig` | A configuration structure for generating proxy types and equivalences. Fields: `proxyName`, `proxyEquivName`, `mkCtorProxyType`, `mkProxyType`. |
| `defaultMkCtorProxyType` | Constructs a proxy type for a single constructor using `Unit`, `PLift`, `Sigma`. Returns `(proxyType, pattern)`. Avoids `PSigma` for better typeclass inference. |
| `defaultMkProxyType` | Builds the full proxy type as a nested `Sum` (optimized to avoid trailing `Empty`). Returns `(proxyType, constructor patterns, left_inv proof tactic)`. |
| `ProxyEquivConfig.default` | Default config: names `proxyType` and `proxyTypeEquiv` in the inductive type’s namespace; uses default `mkCtorProxyType`/`mkProxyType`. |
| `ensureProxyEquiv` | Main logic: checks non-recursiveness & no indices, builds proxy type & equivalence, defines `proxyType` and `proxyTypeEquiv`, adds docstrings, sets attributes. |
| `elabProxyEquiv` | Helper for elaborator: elaborates type, validates expected type (`_ ≃ α`), retrieves `InductiveVal`. |
| `proxy_equiv%` | Term elaborator syntax: `proxy_equiv% t` produces `β ≃ t` for proxy type `β`. Side-effect: defines `t.proxyType` and `t.proxyTypeEquiv`. |

#### **2. Naming Conventions**

- **Prefixes**:

  - `default*`: Default implementations (`defaultMkCtorProxyType`, `defaultMkProxyType`).

  - `*Type`: Proxy type expressions (`proxyType`, `ctype`, `xsty`).
  - `*patt` / `*patt*`: Patterns for matching (`ppatt`, `cpatt`, `patts`).

#### **3. Tactic Stack**

Frequently used tactics in proofs and elaboration:
- `rfl` — for reflexivity in `right_inv`.
- `cases x` / `cases x with | inl _ => rfl | inr x => $pf:tactic` — for case analysis on `Empty`, `Sum`.
- `intro x` — used in `left_inv` proof generation.
- `nomatch x` — for empty inductive types (0 constructors).
- `isDefEq` — used in validation checks (e.g., redefinition safety).
- `whnf` — used during elaboration to normalize types.

#### **4. Proof Logic & Flow**

- **Inductive type constraints**:
  - Must be non-recursive (`indVal.isRec = false`).
  - Must have zero indices (`indVal.numIndices = 0`).
- **Construction steps**:
  1. For each constructor, build:
     - Proxy type for arguments (`defaultMkCtorProxyType`).
     - Constructor pattern (`cpatt`) and proxy pattern (`ppatt`).
  2. Combine constructor proxy types into total proxy type via `Sum` (`defaultMkProxyType`).
  3. Build match alternatives for `toFun` (proxy → original) and `invFun` (original → proxy).
  4. Prove `right_inv` by `intro x; cases x <;> rfl`.
  5. Prove `left_inv` using the tactic `pf` generated by `mkCType`.
- **Equivalence definition**:
  ```lean
  { toFun := fun $toFunAlts,
    invFun := fun $invFunAlts,
    right_inv := by intro x; cases x <;> rfl,
    left_inv := by intro x; $pf }
  ```

### **Design Highlights**

- **Proxy type structure**: `C₁ ⊕ (C₂ ⊕ ⋯ ⊕ Cₙ)` (quadratic in number of constructors due to nesting).
- **Avoids `PSigma`**: Uses `Sigma` directly for better `Fintype` inference.
- **Typeclass-friendly**: Proxy type is marked `reducible` so typeclass inference can unfold it.
- **Idempotent**: Re-running `proxy_equiv%` on same type checks existing definitions for correctness.
