### Technical Metadata Brief: `clean%` Term Elaborator

---

#### **1. Key Definitions & Theorems**

| Name | Type / Signature | Purpose |
|------|------------------|---------|
| `cleanConsts` | `List Name` | List of constant names (currently only `id`) that are definitionally equal to `id` and should be removed by `clean`. |
| `clean` | `Expr → Expr` | Recursively eliminates identity functions (`id`), η-expansions (`fun x => x`), and tautological `let_fun` bindings (e.g., `let_fun x := y in x`) from an expression. |
| `elabClean` | `Term.TermElab` | Elaborator for the `clean%` syntax: elaborates a term, instantiates metavariables, and applies `clean`. |
| `cleanStx` | Syntax rule | Syntax declaration for `"clean% " term`. |

> **Note**: No theorems are proven in this file — it is a *tactic/term elaborator implementation*, not a logical development.

#### **2. Naming Conventions**

- **Prefixes**:
  - `clean%`: Custom syntax prefix for term-level cleaning.
  - `clean`: Core function name (also used in deprecated tactic form `clean`).
- **Suffixes**:
  - `%`: Indicates *term-level* syntax (as opposed to tactic-level), following Lean’s convention for term elaborators (e.g., `simp%`, `rw%`).
- **Constants**:
  - `cleanConsts`: Descriptive plural noun, lists constants to eliminate.
  - `cleanStx`: Combines `clean` + `Stx` (short for *syntax*), following Lean’s tactic syntax naming (e.g., `tacticElabStx`).

---

#### **4. Proof Logic / Implementation Flow**

The `clean` function uses structural recursion via `Expr.replace` with pattern matching:

1. **`id` elimination**:
   - Matches `id t p` (i.e., `@id _ p`) as `.app (.app (.const ``id _) _) e'` and replaces with `e'`.
2. **η-expansion elimination**:
   - Matches `fun x => x` applied to an argument: `fun x => x $ e'` → `e'`.
3. **Tautological `let_fun` elimination**:
   - Matches `let_fun x := v in x` → `v`.

The elaborator `elabClean`:
- Parses `clean% t`.
- Elaborates `t` with full synthesis (`Term.withSynthesize`).
- Instantiates metavariables (`instantiateMVars`).
- Applies `clean` to the resulting expression.

> **No induction or case analysis** — purely syntactic simplification.

### Summary

This file defines a **syntactic simplifier** for removing redundant identity functions and η-expansions from Lean terms, primarily used to clean up terms generated by `dsimp`, `show`, or type annotations. It follows Lean’s term elaborator pattern and is part of `Mathlib.Tactic`, indicating its role as a *utility tactic* for term normalization.
