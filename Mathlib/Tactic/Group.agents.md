### Technical Metadata Brief: `group` Tactic in Lean 4 (Mathlib)

---

#### **1. Key Definitions & Theorems**

| Name | Type / Signature | Purpose |
|------|------------------|---------|
| `zpow_trick` | `∀ {G : Type*} [Group G] (a b : G) (n m : ℤ), a * b ^ n * b ^ m = a * b ^ (n + m)` | Enables merging consecutive powers of the same element into a single power with summed exponent. Used to prepare expressions for exponent normalization. |
| `zpow_trick_one` | `∀ {G : Type*} [Group G] (a b : G) (m : ℤ), a * b * b ^ m = a * b ^ (m + 1)` | Special case of `zpow_trick` for multiplying by `b` on the right (i.e., exponent +1). |
| `zpow_trick_one'` | `∀ {G : Type*} [Group G] (a b : G) (n : ℤ), a * b ^ n * b = a * b ^ (n + 1)` | Special case for multiplying by `b` on the left (i.e., exponent +1). |
| `aux_group₁` | Syntax tactic | Applies `simp` with a curated list of group-theoretic rewrites (including `zpow_*` lemmas, `mul_assoc`, etc.) to normalize structure *without* touching exponents yet. |
| `aux_group₂` | Syntax tactic | Applies `ring_nf` to normalize integer exponents (e.g., simplify `n + 1 - 1` to `n`, or `0` to collapse terms). |
| `group` | Syntax tactic | Repeatedly applies `aux_group₁` followed by `aux_group₂` until no further progress is made — enabling iterative simplification (e.g., after `ring` reduces an exponent to `0`, the simplifier can remove the identity). |

> **Note**: All `zpow_*` lemmas are marked with `@[to_additive]`, indicating they have additive counterparts for use in additive contexts (e.g., `abel` tactic).

---

#### **2. Naming Conventions**

- **Prefixes**:
  - `zpow_*`: For lemmas involving integer powers (`zpow` = "integer power").
  - `aux_group*`: For internal helper tactics (`aux_group₁`, `aux_group₂`).
- **Suffixes**:
  - `_trick`, `_one`, `_one'`: Denotes specialized rewriting lemmas for common patterns.
  - `_def`: Used in `commutatorElement_def`, likely for definitional unfolding.

---

#### **3. Tactic Stack**

The tactic relies on the following core tactics in sequence and repetition:

| Tactic | Role |
|--------|------|
| `simp` | Rewrites using a large set of group axioms and `zpow`-related lemmas; excludes `decide` and `failIfUnchanged`. |
| `ring_nf` | Normalizes integer arithmetic in exponents (e.g., simplifies `n - m + 1` to canonical form). |
| `fail_if_no_progress` | Ensures the loop terminates: stops if neither `aux_group₁` nor `aux_group₂` makes progress. |
| `repeat` | Loops the combined `aux_group₁ <;> aux_group₂` until stuck. |
| `<;>` | Sequential composition: applies second tactic to all subgoals generated by the first. |

---

#### **4. Proof Logic / Strategy**

- **Goal**: Normalize arbitrary group expressions (e.g., `a * b * b⁻¹ * c * d² * d⁻³`) into a canonical form (e.g., `a * c * d⁻¹`).
- **Approach**:
  1. **Structural simplification (`aux_group₁`)**:
     - Uses `simp` to push inverses inward, collapse `1`, rearrange via `mul_assoc`, and combine adjacent powers of the *same* element using `zpow_*` lemmas.
     - Leaves exponents unevaluated (e.g., `b ^ (2 + (-1))` remains).
  2. **Exponent normalization (`aux_group₂`)**:
     - Applies `ring_nf` to simplify integer expressions in exponents (e.g., `2 + (-1) ↦ 1`, `n - n ↦ 0`).
  3. **Iteration**:
     - After exponent simplification, some factors may become `b ^ 0 = 1`, which `simp` can then eliminate in the next `aux_group₁` pass.
     - Repeats until no further changes occur.

- **Key Insight**: The interaction between `simp` (structural) and `ring` (exponent arithmetic) requires iteration because simplification can expose new exponent simplifications.

---

#### **5. Imports & Dependencies**

| Import | Purpose |
|--------|---------|
| `Mathlib.Tactic.Ring` | Provides `ring_nf`, used in `aux_group₂` to normalize integer exponents. |
| `Mathlib.Tactic.FailIfNoProgress` | Enables `fail_if_no_progress`, critical for loop termination. |
| `Mathlib.Algebra.Group.Commutator` | Supplies `commutatorElement_def`, used in `simp` set (though likely unused in pure group normalization — possibly for future extensibility or related tactics). |

> **Note**: The tactic does **not** assume commutativity (unlike `abel`). It works in *non-abelian* groups using only group axioms.

---

### Summary

The `group` tactic is a **structural normalizer** for multiplicative groups, combining:
- A **simplifier pass** (`aux_group₁`) to rearrange and combine like terms,
- A **ring pass** (`aux_group₂`) to simplify integer exponents,
- **Iteration** to handle cascading simplifications (e.g., exponent → 0 → identity removal).

It exemplifies Lean’s tactic composition pattern: leveraging existing automation (`simp`, `ring`) in a domain-specific loop.
