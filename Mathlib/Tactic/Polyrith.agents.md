### Technical Metadata Brief: `polyrith` Tactic (Lean 4)

---

#### **1. Key Definitions & Theorems**

| Name | Type / Signature | Purpose |
|------|------------------|---------|
| `Poly` | `inductive Poly` | Semantic representation of multivariate polynomials over `ℚ`, supporting constants, variables, hypotheses, arithmetic operations, and negation. |
| `Poly.format` | `Poly → Format` | Converts a `Poly` into a valid Python string representation (for SageMath API). |
| `Poly.toSyntax` | `Poly → Unhygienic Syntax.Term` | Reifies a `Poly` into a Lean syntax term usable by `linear_combination`. |
| `parse` | `{α : Type u} [CommSemiring α] → Expr → AtomM Poly` | Reifies a Lean expression of type `α` into a `Poly`, handling ring operations and constants. |
| `Source` | `inductive Source` | Represents sources of hypotheses: either from local context (`fvar`) or user-provided list (`input`). |
| `parseContext` | `Bool → Array Expr → Expr → AtomM (Expr × Array (Source × Poly) × Poly)` | Parses the goal and hypotheses into a normalized form: target polynomial (`tgt`) and list of hypothesis polynomials with sources. |
| `createSageArgs` | `Bool → Expr → Nat → Array (Source × Poly) → Poly → Array String` | Constructs command-line arguments for the external SageMath script. |
| `Poly.unNeg?`, `Poly.add'`, `Poly.mul'`, `Poly.unDiv?`, `Poly.pow'` | Various `Poly → ...` | Helper functions for simplifying polynomial representations (e.g., `a + -b ↦ a - b`, `1 * a ↦ a`). |
| `SageCoeffAndPower` | `structure` | Holds Sage’s output: array of coefficient polynomials and exponent (`power`) for the goal. |
| `polyrith` | `MVarId → Bool → Array Expr → MetaM (Except MVarId (TSyntax `tactic))` | Main tactic logic: parses context, calls Sage via Python, parses result, and constructs a `linear_combination` tactic. |
| `sageOutput` | `Array String → IO SageResult` | Executes `scripts/polyrith_sage.py` and parses JSON output. |

**Theorem-like behavior (implicit)**:  
The tactic is *sound* under the assumption that Sage correctly computes Gröbner basis representations — i.e., if `polyrith` succeeds, then the goal follows from the hypotheses via a certificate expressible as a linear combination (possibly of a power of the goal) in the ideal/radical.

#### **2. Naming Conventions**

- **Prefixes**:
  - `Poly.`: All core polynomial operations and conversions.
  - `parse`: Reification functions (`parse`, `parseContext`).
  - `create`: Data preparation (`createSageArgs`).
  - `un*?`: Optional simplifications (`unNeg?`, `unDiv?`).
  - `*'?`: Simplified variants (`add'`, `mul'`, `pow'`).
- **Suffixes**:
  - `?`: Optional-returning functions (e.g., `unNeg? : Poly → Option Poly`).
  - `M`: Monadic functions (`sumM`, `toSyntax` uses `Unhygienic.run`).
- **Other**:
  - `hyp`: Used for hypothesis references (`hyp : Term → Poly`).
  - `varN`: Python variable naming convention (e.g., `var0`, `var1`) in `format`.

#### **3. Tactic Stack**

- **Core tactics used**:
  - `ring`: To close trivial goals or fallback.
  - `linear_combination`: Primary certificate-checking tactic; `polyrith` *synthesizes* coefficients for it.
  - `norm_num`: Used internally in `parse` to extract rational constants.
- **Internal monads**:
  - `AtomM`: For reification and local context manipulation.
  - `MetaM`: For tactic execution and goal manipulation.
  - `IO`: For external script execution.

**Tactics in generated code**:
- `linear_combination`
- `linear_combination (exp := n)`
- `ring` (fallback)

---

#### **4. Proof Logic / Strategy**

1. **Goal parsing**:
   - Infer the type `α` of the equality (must be a `CommSemiring`).
   - Normalize the goal into `e₁ = e₂`, then reify `e₁ - e₂` as a `Poly`.

2. **Hypothesis collection**:
   - If `only` is false: scan local context for equalities over `α`.
   - Append user-provided hypotheses/proof terms.
   - Reify each hypothesis as `lhs - rhs : Poly`.

3. **External computation (Sage)**:
   - Send hypotheses + target to Sage via `scripts/polyrith_sage.py`.
   - Sage computes whether the target lies in the *radical* of the ideal generated by hypotheses.
   - Returns coefficients (`coeffs`) and exponent (`power`) such that:
     ```
     (target)^power = Σ coeffs[i] * hypothesis[i]
     ```

4. **Certificate construction**:
   - Convert Sage’s `coeffs` (as `Poly`s) into Lean syntax terms.
   - Handle simplifications (e.g., division by integer, negation).
   - Construct a `linear_combination` tactic call:
     - If `power = 1`: `linear_combination c₁ h₁ + … + cₙ hₙ`
     - If `power > 1`: `linear_combination (exp := power) (c₁ h₁ + … + cₙ hₙ)`
     - If all coeffs zero: `linear_combination`

5. **Verification**:
   - Run the generated `linear_combination` tactic.
   - On success: suggest the tactic to the user.
   - On failure: report internal error.

### Summary

`polyrith` is a *certificate synthesis* tactic for polynomial goals over fields, leveraging Gröbner basis computations via SageMath. It automates the manual coefficient-finding step of `linear_combination`, using algebraic geometry (radical membership) to find certificates — possibly involving powers of the goal. Its design reflects a clean separation between Lean-side reification/parsing and Python/Sage-side computation.
