### **1. Key Definitions & Theorems**

| Name | Type / Syntax | Purpose |
|------|---------------|---------|
| `eqnsAttribute` | `NameMapExtension (Array Name)` | Stores user-provided equation lemmas for declarations, overriding Lean’s default `eqns`-generated lemmas. |
| `registerGetEqnsFn` | `Lean.Meta.registerGetEqnsFn` | Registers a custom handler (`eqnsAttribute.find?`) to retrieve user-specified equation lemmas for a given declaration name. |
| `eqns` syntax | `(name := eqns) "eqns" (ppSpace ident)* : attr` | Attribute syntax allowing users to attach a list of theorem names as equation lemmas for a function. |

> **Note**: No theorems are *proven* in this file — it is purely infrastructure for *attaching* equation lemmas.

### **4. Proof Logic / Implementation Flow**

- **Registration phase**:
  1. Define syntax for `@[eqns ...]`.
  2. Initialize `eqnsAttribute` as a `NameMapExtension`.
  3. Register a handler via `registerGetEqnsFn` to override `Lean.Meta.getEqnsFn`.
- **Attribute application**:
  - On `@[eqns t1 t2] f`, parse theorem names `t1, t2`, resolve them to `Name`s, and store them under `f` in the `eqnsAttribute` map.
  - Reject duplicate registration for same `declName`.
- **Usage**:
  - When Lean needs equation lemmas for `f`, it calls the registered `getEqnsFn`, which consults `eqnsAttribute`.
  - This allows `rw [f]` to use user-specified lemmas instead of default `f._match_1`, etc.

### **Summary**

This file implements a **user-extensible equation lemma override system** in Lean 4. It enables users to replace default equation lemmas (e.g., generated by `def`/`match`) with custom theorems via the `@[eqns ...]` attribute, improving rewrite behavior and definitional equality reasoning. The implementation is minimal, relying on Lean’s metaprogramming infrastructure for attribute registration and equation lookup.
