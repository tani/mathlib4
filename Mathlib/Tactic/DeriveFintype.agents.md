### Technical Metadata Brief: `Mathlib.Deriving.Fintype`

---

#### **1. Key Definitions & Theorems**

| Name | Type / Purpose |
|------|----------------|
| `derive_fintype%` | **Term elaborator macro** (`macro`): Synthesizes a `Fintype α` instance via `Fintype.ofEquiv _ (proxy_equiv% α)`. Enables manual derivation with explicit assumptions (e.g., `DecidableEq`). |
| `mkFintype` | **Command elaborator** (`def mkFintype : Name → CommandElabM Bool`): Generates a `Fintype` instance for non-enum inductive types by adding `Fintype`/`Decidable` instances for all type/prop parameters, then invoking `derive_fintype%`. |
| `mkFintypeEnum` | **Command elaborator** (`def mkFintypeEnum : Name → CommandElabM Unit`): Optimized handler for *enum* types (zero-ary constructors). Constructs: <br> • `enumList`: list of all constructors <br> • `enumList_get?_to_CtorIdx_eq`: theorem that `toCtorIdx` maps `enumList` elementwise <br> • `enumList_nodup`: proof of injectivity (via `List.Nodup`) <br> • Final `Fintype` instance via `Finset.mk`. |
| `mkFintypeInstanceHandler` | **Handler registration function** (`def mkFintypeInstanceHandler : Array Name → CommandElabM Bool`): Dispatches to `mkFintypeEnum` (for enum types) or `mkFintype` (otherwise). Rejects mutually inductive types (`size ≠ 1`). |
| `proxy_equiv%` | **Implicit term elaborator** (used via `derive_fintype%`): Constructs an equivalence `α ≃ proxyType α`, where `proxyType` is built from `Sum`, `ULift`, etc., using type parameters’ `Fintype` instances. |
| `toCtorIdx` | **Intrinsic function** (for enum types): Maps each constructor to a unique natural index (used in `mkFintypeEnum`). |

---

#### **2. Naming Conventions**

- **Prefixes**:
  - `mkFintype*`: Functions that *construct* `Fintype` instances.
  - `enumList*`: Related to the explicit enumeration of constructors (enum types only).
  - `toCtorIdx*`: Theorems about the constructor-indexing function.
- **Suffixes**:
  - `Name`: Refers to `Name`-based identifiers (e.g., `enumListName`, `toCtorThmName`).
  - `%`: Indicates *term elaborators* (`derive_fintype%`, `proxy_equiv%`).
- **Pattern**:
  - `declName.mkStr "..."`: Constructs internal names (e.g., `MyOption.enumList`).
  - `setProtected`: Ensures generated names are in the type’s namespace.

#### **3. Tactic Stack**

Frequently used tactics in proofs generated by this module:

| Tactic | Role |
|--------|------|
| `intro x; cases x <;> rfl` | Structural induction + definitional equality for enum proofs. |
| `apply List.Nodup.of_map ...; exact ...` | Proves list injectivity via mapping to `List.range`. |
| `rw [Finset.mem_mk, Multiset.mem_coe, List.mem_iff_get?]` | Rewrites membership in `Finset.mk` to `List.get?`. |
| `have h := rfl; exact h ▸ ...` | Uses definitional equality (`rfl`) to rewrite goals. |
| `Term.synthesizeSyntheticMVarsNoPostponing` | Forces resolution of all metavariables before committing theorems. |

*Note*: No heavy automation (e.g., `aesop`, `ring`) — proofs are mostly syntactic or definitional.

---

#### **4. Proof Logic**

- **For enum types** (`mkFintypeEnum`):
  1. **Construct `enumList`**: List of all constructors (order preserved).
  2. **Prove correctness**: `List.get? enumList (toCtorIdx x) = some x`.
  3. **Prove injectivity**: `List.Nodup enumList` via `List.map toCtorIdx enumList = List.range n`.
  4. **Define `Fintype`**: `Finset.mk enumList nodup` + completeness proof.

- **For non-enum types** (`mkFintype` → `derive_fintype%`):
  1. **Build proxy type**: `C₁ ⊕ (C₂ ⊕ ⋯ ⊕ Cₙ)` (nested `Sum`s of constructor types).
  2. **Synthesize `Fintype` on proxy**: Via assumptions (e.g., `Fintype α` for parameters).
  3. **Pull back instance**: `Fintype.ofEquiv _ (proxy_equiv% α)`.

- **Complexity**:
  - Enum: $O(n)$ (linear in constructors).
  - Non-enum: $O(n^2)$ worst-case due to nested `Sum` projections (acknowledged in docstring).

### Summary

This module automates `Fintype` instance generation for inductive types via two strategies:
- **Enum types**: Explicit enumeration + injectivity proofs.
- **General types**: Proxy type + equivalence-based transfer.

It prioritizes *computational efficiency* (e.g., `enumList` for enums) and *modularity* (reusing `Fintype` for parameters), while avoiding recursive/indexed types. The design reflects Lean 4’s elaborator framework and draws inspiration from Mathlib 3’s approach.
