### Technical Metadata Brief: Pushforward Quiver Structure in Lean 4

---

#### **1. Key Definitions & Theorems**

| Name | Type / Signature | Purpose |
|------|------------------|---------|
| `Push σ` | `Type u₂` (when `σ : V → W`) | Underlying type for the pushed quiver; identical to `W`. |
| `PushQuiver σ` | `W → W → Type (max u u₂ v)` | Inductive family of arrows: generated by `PushQuiver.arrow : (f : X ⟶ Y) → PushQuiver σ (σ X) (σ Y)`. |
| `instance : Quiver (Push σ)` | `Quiver (Push σ)` | Equips `Push σ ≡ W` with the quiver structure `PushQuiver σ`. |
| `of σ` | `V ⥤q Push σ` | The canonical prefunctor induced by `σ`: acts as `σ` on objects and maps `f` to `PushQuiver.arrow f`. |
| `lift σ φ τ h` | `Push σ ⥤q W'` | Extension of `τ : W → W'` to a prefunctor, assuming `φ = τ ∘ σ` on objects (`h : ∀ x, φ.obj x = τ (σ x)`). |
| `lift_obj` | `(lift σ φ τ h).obj = τ` | Trivial equality of object maps. |
| `lift_comp` | `of σ ⋙q lift σ φ τ h = φ` | The universal property: factoring `φ` through `of σ` via `lift`. |
| `lift_unique` | Uniqueness of `lift`: if `Φ` satisfies `Φ.obj = τ` and `of σ ⋙q Φ = φ`, then `Φ = lift σ φ τ h`. | |

#### **2. Naming Conventions**

- **Prefixes**:
  - `Push*`: for constructions related to the pushforward quiver (`Push`, `PushQuiver`, `Push.of`, `Push.lift`).
  - `of`, `lift`: standard categorical naming for canonical morphisms in universal constructions.
- **Suffixes**:
  - `_obj`, `_map`, `_comp`, `_unique`: for projection or property theorems about components or uniqueness.
- **Variable naming**:
  - `σ`, `τ`: functions between types (object mappings).
  - `φ`, `Φ`: prefunctors.
  - `X`, `Y`, `f`: typical quiver/morphism variables.

- **Core tactics**:

- **Pattern**:
  - Heavy use of `simp only` with `Prefunctor.comp_obj`, `Prefunctor.comp_map`, and `cast_eq`.
  - Manual handling of heterogeneous equality (`HEq`) and transport (`cast`, `p ▸ b`) in `lift_comp`.
  - `iterate 2 apply` used for repeated application of a lemma.

---

#### **4. Proof Logic**

- **Structure**:
  - **Inductive definition** of `PushQuiver` ensures arrows are generated solely from arrows in `V` via `σ`.
  - **`lift` definition** uses `PushQuiver.rec` to define the action on arrows by recursion on the inductive family.
  - **`lift_comp` proof**:
    - Uses `Prefunctor.ext` to reduce to object and map parts.
    - Object part: follows directly from `h`.
    - Map part: requires careful handling of heterogeneous equality due to dependent type theory subtleties (transport along `h X`, `h Y`).
  - **`lift_unique` proof**:
    - Again uses `Prefunctor.ext`.
    - Object part uses `Φ₀`.
    - Map part uses `Φcomp` and simplifies using `cast_eq` and `eqRec_heq`.

- **Logical flow**:
  - Define structure → prove universal property (existence + uniqueness) → verify coherence with composition.
