### Technical Metadata Brief: Sums of Squares in Lean 4

---

#### **1. Key Definitions & Theorems**

| Name | Type / Signature | Purpose |
|------|------------------|---------|
| `IsSumSq` | `inductive IsSumSq [Add R] [Zero R] : R → Prop` | Inductive predicate defining *sums of squares* in a type `R` with `+`, `0`, `*`. |
| `sumSqIn` | `def sumSqIn [AddMonoid R] : AddSubmonoid R` | Submonoid of `R` consisting of all sums of squares (carrier = `{S | IsSumSq S}`). |
| `IsSumSq.add` | `{S1 S2 : R} → IsSumSq S1 → IsSumSq S2 → IsSumSq (S1 + S2)` | Closure under addition: sum of two sums of squares is a sum of squares. |
| `IsSumSq.sum_mul_self` | `(s : Finset ι) → (f : ι → R) → IsSumSq (∑ i ∈ s, f i * f i)` | Finite sums of squares (via `∑ f i * f i`) are sums of squares. |
| `mem_sumSqIn_of_isSquare` | `{x : R} → IsSquare x → x ∈ sumSqIn R` | Every square (`x = y * y`) lies in `sumSqIn R`. |
| `AddSubmonoid.closure_isSquare` | `closure {x | IsSquare x} = sumSqIn R` | The submonoid generated by all squares equals the set of sums of squares. |
| `IsSumSq.nonneg` | `{S : R} → IsSumSq S → 0 ≤ S` | In a linearly ordered semiring with `ExistsAddOfLE`, sums of squares are non-negative. |

---

#### **2. Naming Conventions**

- **Predicates**: `IsSumSq`, `IsSquare` — standard `is_` prefix for properties.
- **Constructors**: `zero`, `sq_add` — descriptive names for inductive constructors.
- **Types/structures**: `sumSqIn` — camelCase, no `is_` prefix; reflects *the object* (submonoid) of sums of squares.
- **Theorems**:
  - `add`, `sum_mul_self`, `nonneg`, `mem_...`, `closure_...` — follow standard Mathlib conventions.
  - `mem_sumSqIn_of_isSquare`: `mem_..._of_...` pattern for membership proofs based on another property.
  - `AddSubmonoid.closure_isSquare`: `closure_...` for closure-related equalities.

---

#### **3. Tactic Stack**

- **Core tactics**: `induction`, `rw`, `simp only`, `exact`, `refine`.
- **Order-specific**: `add_nonneg`, `sq_nonneg`, `le_refl`, `simp only [pow_two]`.
- **Finset reasoning**: `Finset.cons_induction`, `Finset.sum_cons`, `Finset.sum_empty`.
- **Submonoid reasoning**: `closure_le`, `subset_closure`, `add_mem`, `zero_mem`.
- **No heavy automation**: No `aesop`, `linarith`, or `ring` used — proofs are mostly structural/inductive.

---

#### **4. Proof Logic**

- **Inductive structure** dominates:
  - Proofs about `IsSumSq` proceed by induction on its constructors (`zero`, `sq_add`).
  - For `IsSumSq.add`: induct on `p1`; base case uses `zero_add`; step uses `sq_add` + `add_assoc`.
  - For `IsSumSq.nonneg`: induct on `pS`; base case uses `le_refl`; step uses `add_nonneg` + `sq_nonneg`.
  - For `AddSubmonoid.closure_isSquare`: use `le_antisymm`; one direction via `closure_le`, the other via induction on `hx : x ∈ sumSqIn R`.
- **Rewriting & simplification** are minimal and precise (`rw`, `simp only`), avoiding over-simplification.
- **Dependent elimination** (e.g., `rcases px with ⟨y, py⟩`) used to unpack existential/structure data.
