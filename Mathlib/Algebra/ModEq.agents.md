#### **1. Key Definitions & Theorems**

| Name | Type / Signature | Purpose |
|------|------------------|---------|
| `ModEq` | `def ModEq (p a b : α) : Prop := ∃ z : ℤ, b - a = z • p` | Defines congruence modulo `p` in an additive commutative group: `a ≡ b [PMOD p]` iff `b - a` is an integer multiple of `p`. |
| `modEq_refl` | `a ≡ a [PMOD p]` | Reflexivity of congruence. |
| `modEq_comm` | `a ≡ b [PMOD p] ↔ b ≡ a [PMOD p]` | Symmetry of congruence. |
| `ModEq.trans` | `a ≡ b [PMOD p] → b ≡ c [PMOD p] → a ≡ c [PMOD p]` | Transitivity of congruence. |
| `modEq_zero` | `a ≡ b [PMOD 0] ↔ a = b` | Congruence modulo `0` is equality. |
| `modEq_sub` | `a ≡ b [PMOD b - a]` | Trivial congruence: any element is congruent to another modulo their difference. |
| `zsmul_modEq_zero` | `z • p ≡ 0 [PMOD p]` | Integer multiples of `p` are congruent to `0` modulo `p`. |
| `add_zsmul_modEq` | `a + z • p ≡ a [PMOD p]` | Adding a multiple of `p` doesn’t change congruence class. |
| `modEq_iff_eq_add_zsmul` | `a ≡ b [PMOD p] ↔ ∃ z, b = a + z • p` | Equivalent formulation using addition instead of subtraction. |
| `modEq_iff_eq_mod_zmultiples` | `a ≡ b [PMOD p] ↔ (b : α ⧸ AddSubgroup.zmultiples p) = a` | Congruence corresponds to equality in the quotient by the cyclic subgroup generated by `p`. |
| `zsmul_modEq_zsmul` | `[NoZeroSMulDivisors ℤ α] → z ≠ 0 → (z • a ≡ z • b [PMOD z • p] ↔ a ≡ b [PMOD p])` | Cancellation of nonzero integer scalars in congruence. |
| `div_modEq_div` (in `DivisionRing`) | `c ≠ 0 → (a / c ≡ b / c [PMOD p] ↔ a ≡ b [PMOD p * c])` | Division interacts with congruence via scaling the modulus. |
| `mul_modEq_mul_left` (in `Field`) | `c ≠ 0 → (c * a ≡ c * b [PMOD p] ↔ a ≡ b [PMOD p / c])` | Multiplication by nonzero scalar cancels in congruence, scaling modulus accordingly. |

#### **2. Naming Conventions**

- **Prefixes**:
  - `modEq_`: for basic properties (e.g., `modEq_refl`, `modEq_comm`, `modEq_zero`).
  - `ModEq.`: for lemmas inside the `ModEq` namespace (e.g., `ModEq.trans`, `ModEq.add`, `ModEq.zsmul`).
  - `add_`, `sub_`, `zsmul_`, `nsmul_`, `mul_`, `div_`: indicate operation involved (addition, subtraction, integer/natural scalar mult, multiplication, division).
- **Suffixes**:
  - `_modEq`: for congruence lemmas (e.g., `add_zsmul_modEq`, `zsmul_add_modEq`).
  - `_iff_`: for biconditional characterizations (e.g., `modEq_iff_eq_add_zsmul`, `div_modEq_div`).
  - `_cancel`: for cancellation lemmas (e.g., `zsmul_cancel`, `add_left_cancel`).
  - `of_`, `neg`, `symm`: for direction aliases (e.g., `ModEq.of_neg`, `ModEq.neg`, `ModEq.symm`).

#### **3. Tactic Stack**

Frequently used tactics in proofs:
- `simp`: Dominant tactic for simplifying `ModEq`, `sub`, `smul`, `zsmul`, `nsmul`, `add`, `neg`, and quotient equalities.
- `rw`: Rewriting using definitions (`modEq_iff_eq_add_zsmul`, `QuotientAddGroup.eq_iff_sub_mem`, etc.).
- `exists_congr`: To transform existential quantifiers (e.g., in `zsmul_modEq_zsmul`, `nsmul_modEq_nsmul`).
- `rwa`: Combine `rw` and `assumption` (e.g., in `ModEq.of_zsmul`).
- `norm_cast`: For lifting congruences across type embeddings (e.g., `intCast_modEq_intCast`).
- `aesop`: Likely used implicitly (not visible here, but standard in Mathlib for routine goals).
- `symm`, `trans`: Applied via `apply` or `exact` in manual proof steps.

#### **4. Proof Logic**

- **Structure**: Most proofs follow a pattern:
  1. **Unfold definition** (`ModEq`) → `∃ z, b - a = z • p`.
  2. **Construct witness** (e.g., `0`, `1`, `-z`, `m + n`, `m * z`) and simplify.
  3. Use algebraic identities (`add_smul`, `sub_smul`, `smul_comm`, `mul_smul`, `one_smul`, etc.).
  4. For biconditionals: apply `exists_congr` + `simp` or use equivalences like `Equiv.addLeft`.
  5. For quotient-based lemmas: use `QuotientAddGroup.eq_iff_sub_mem` + `AddSubgroup.mem_zmultiples_iff`.
- **Induction**: Not used here (no natural-number induction needed beyond `nsmul` lemmas, which are handled via `zsmul` or direct witness).
- **Case analysis**: Rare; mostly algebraic manipulation.
